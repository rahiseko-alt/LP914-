## 判定不能12件のうち10件は、たった1つの未確認事項から出ている

このアプリの画面には、パスワードを入れる欄が1つも無い。ログインは Google のみである
（`backend/js/supabase-auth.js:62, 441`）。しかし**利用者を管理している仕組みの側で、
メールとパスワードによるログインが止めてあるか**が、どの情報源にも書かれていない。

止めていなければ、画面を通さずに直接ログインされる道が残る。そうなるとパスワードに
関する8項目（6.2.1〜6.2.8）がすべて効いてくる。この1点が分かれば、**8項目が一度に
確定する**。

同様に、ログインし直したときの合言葉の入れ替え（7.2.4）とログアウト後の無効化（7.4.1）も、
その仕組みの挙動が記録に無いため判定不能になっている。

**この4点を確かめれば、判定不能は12件から2件に減る。** 残る2件は認証の文書（6.1.1）と
その実装（6.3.1）で、これは文書を書けば解消する。

回数制限の仕組み自体は存在する（`supabase/migrations/202607160001_supabase_base.sql:538` の

### v5.0.0-6.2.1〜6.2.8 — パスワードに関する8項目

**判定: 8項目すべて 判定不能**

共通の但し書きの2条件を、どちらも満たさなかった。

**条件1（【パスワード検索】の出力が0件）**: 1件出た。

```
./scripts/lib/local-stack.mjs:108: type=password
```

その行を読んだところ、**手元での試験専用の道具**だった。同ファイルの冒頭に、手元の
Supabase を起動して検証するための共通部品であり、本番の鍵を使わないと明記されている
（`scripts/lib/local-stack.mjs:1-8`）。`:105-106` にも「ログイン画面は Google 認証のみを
表示するので、これは試験専用の裏口」と書かれている。

本番の画面にパスワード入力は無い。しかし**合格基準は「出力が0件であること」と定めており、
1件出た以上、条件1は満たさない**。基準をその場で緩めない。

**条件2（利用者を管理している仕組みの側でパスワードによるログインが止めてあることが記録に
ある）**: 記録には「本番の画面は Google 認証のみを表示する」とあるだけで
（`docs/handoff.md:3713`）、**仕組みの側で止めてあるとは書かれていない**。画面に出さない
ことと、受け付けないことは別である。

対象の8項目: 6.2.1（最低文字数）／6.2.2（変更できる）／6.2.3（いまのパスワードを求める）／
6.2.4（よく使われるパスワードを弾く）／6.2.5（文字種を強制しない）／6.2.6（伏せ字）／
6.2.7（貼り付けを妨げない）／6.2.8（そのまま照合する）

なお 6.2.6 と 6.2.7 の命令はどちらも**出力0件**だった（伏せ字でない入力欄も、貼り付けを
妨げる指定も無い）。それでも共通の但し書きが先に効くため、判定不能のままとする。

**次にやること**: 「利用者を管理している仕組みの側で、メールとパスワードによるログインを
止めてあるか」を1つ確かめて記録する。止まっていれば8項目すべてが「合格（該当機能なし）」に
変わる。止まっていなければ、8項目それぞれを設定に照らして判定することになる。

### v5.0.0-6.4.1 — 仕組みが発行する合言葉が安全か

**判定: 合格**

招待コードが該当する。合格基準の3点をすべて満たす。

1. **安全な乱数**: `encode(extensions.gen_random_bytes(32), 'hex')` で作られている

   生成部）。32バイト＝256ビットで、必要な水準を超えている。時刻や連番ではない。

2. **有効期限がある**: `expires_at` を持ち、引き換え時に `candidate.expires_at > now()` を
   満たさなければ弾かれる（`supabase/migrations/202607160003_invitation_management.sql:22`）。
3. **一度使われたら二度目は通らない**: `claimed_at is null` を条件に取り出し、取り出した
   直後に `claimed_at` を埋める。同時に2人が押しても片方しか通らない作りになっている
   （同ファイル `:20, :29-34`）。

## V7 セッション管理（6項目）

### v5.0.0-7.2.1 — 合言葉の検証がサーバ側で行われているか

**判定: 合格**

ブラウザ側の JavaScript が合言葉の中身を自前で解いて「この人は誰か」を決めている箇所は
無い。検証は2か所のサーバ側で行われている。

- 中継の Cloudflare Worker が、受け取った合言葉をそのまま認証の仕組みに問い合わせて
  確かめている（`worker/src/auth-context.js:44` で `/auth/v1/user` を呼ぶ）。返事が
  芳しくなければ 401 で止める（同 `:55`）。
- データベース側も、行単位のアクセス制御の中で利用者を判定している。

命令の出力に `backend/js/supabase-storage.js:47` の `atob` が出たが、その行を読んだところ
**画像データの変換**（JPEG/PNG/WebP の base64 を戻す処理）であり、合言葉とは無関係だった
（`backend/js/supabase-storage.js:44-50`）。

### v5.0.0-7.2.2 — その都度作られる合言葉を使っているか

**判定: 合格**

利用者の見分けには、ログインのたびに発行される合言葉を使っている
（`worker/src/auth-context.js:39` が受け取り、`:44` で確かめる）。

ブラウザに固定の鍵（`SUPABASE_PUBLISHABLE_KEY`）を置いているが、これは**公開してよい鍵**で
あり、利用者の見分けには使っていない。この鍵だけではデータに到達できず、別に合言葉が要る
ことは、行単位のアクセス制御の判定がすべて利用者の身元に依存していることから確かめられる
（V8 の判定結果を参照）。設定の見本にも公開用の鍵として記載がある（`.env.example:4`）。

### v5.0.0-7.2.3 — 引換券型の合言葉が安全な乱数で作られているか

**判定: 合格（該当機能なし）**

対象アプリ自身がログイン状態の合言葉を作っている箇所は無い。命令の出力に挙がった乱数の
利用は、招待コードの生成（6.4.1 で判定済み）だけだった。`Math.random` の使用は0件。

ログインを外部の仕組みに任せていることは、`backend/js/supabase-auth.js:62-76` と
`worker/src/auth-context.js:44` から特定できる。

### v5.0.0-7.2.4 — ログインのたびに合言葉が入れ替わるか

**判定: 判定不能**

対象アプリ自身は合言葉を作っていないため、入れ替えの挙動は任せ先の仕組みが決めている。
**その挙動が経緯の記録に書かれていない。** 合格基準は「任せ先の名前だけで挙動の記述が
無ければ判定不能」と定めており、そのとおりとした。

### v5.0.0-7.4.1 — ログアウト後に合言葉が使えなくなるか

**判定: 判定不能**

ログアウトの導線は存在する（`backend/js/supabase-auth.js:344-345` の `signOut()`）。
しかしこれがブラウザから消すだけなのか、サーバ側でも通らなくなるのかが、経緯の記録から
判別できない。合格基準は「サーバ側でも無効になることが記録に書かれていること」を求めて
おり、記述が無いため判定不能とした。

### v5.0.0-7.4.2 — 利用者を無効にしたとき、到達できなくなるか

**判定: 合格**

飼い主を退会扱い（`owners.active = false`）にしたとき、その利用者が触りうる**すべての
経路**で到達が止まる。判定は4本あり、そのすべてに `owners.active` の確認が入っている
（`supabase/migrations/202607160007_owner_access_control.sql:47, 64-65, 85-86` ほか）。

この4本は、かつて**1本だけ抜けていて「退会済みに見えるのに見えている」状態だった**ことが
記録されており、その修正として4本に揃えられた経緯がある
（`supabase/migrations/202607160007_owner_access_control.sql:6-12`、
`docs/decisions.md:360`）。抜けが起きうる箇所であることが認識され、塞がれている。

**明記しておくこと**: 合言葉そのものは失効させていない。退会扱いにした利用者の画面は、
見かけ上はログインしたままになる。ただしデータには一切到達できない。合格基準は到達の
可否で判定すると定めているため合格としたが、この事実は隠さず記録する。

## この判定の限界（正直に記録する）

- **本番で動いている設定は見ていない。** 見たのはコードと、手元用の設定ファイルと、経緯の
  記録だけである。判定不能12件のうち10件は、まさにこの限界から出ている。
- `機械` の4項目は何回実行しても同じ結果になる。`読む` の19項目は文章の判断が入るため、
  完全な再現は保証しない。見る場所を命令で絞ることで揺れを抑えている。
- 7.4.2 は、合言葉を失効させていないという事実を含んだうえでの合格である。合格基準を
  「到達できないこと」と定めた結果であり、基準を変えれば判定も変わる。
