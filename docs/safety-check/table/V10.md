# 固定表 — V10 OAuth と OIDC（OAuth and OIDC）

OWASP ASVS 5.0.0 の L1 のうち、この章に属する **5項目**。項目は公式データ
（`../asvs-5.0.0-l1.csv`）と1対1で対応し、追加・削除・統合をしない。

判定のしかたは `機械`（実行する命令が確定しているもの）か `読む`（見る場所が確定している
もの）のどちらか。どちらの命令も、**対象アプリの置き場所の最上位で `bash` で実行する**。

出典: OWASP Application Security Verification Standard 5.0.0 (CC BY-SA 4.0)。
日本語は原文からの訳で、訳の責任はこの置き場所にある（`../../adr/0004` 参照）。

## この章の共通の但し書き

- **命令には3つの種類があり、出力が0件のときの意味が逆になる。** どれに当たるかを各項目の
  「命令の種類」に書く。書いていない命令は使わない。
  - **危険な書き方を探す命令**: 0件なら**合格**。探した書き方をしていない、という意味になる
  - **備えを探す命令**: 0件なら**不合格**。在るべきものが無い、という意味になる
  - **対象の一覧を作る命令**: 0件なら**判定不能**。対象が無いのか、命令が対象アプリの書き方と
    合っていないのかを区別できないため（`../../adr/0002`・`../../adr/0006`）
- **命令の出力に紛らわしい行が出たときは、その行を読む。** 本番の画面から到達できない
  試験専用の道具だと確かめられた場合に限り、その行を数に入れない。確かめられなければ
  数に入れる。**読まずに除外しない。読んだ行はすべて、確かめた結果とともに判定結果に残す。
  出力の一部を無記録で落とさない。**
- **命令は対象アプリの置き場所の最上位で `bash` で実行し、表に書いたとおりに実行する。**
  省略や追加をしない。探す範囲に対象アプリ固有の置き場所の名前を書かない。失敗を
  `2>/dev/null` で隠さない（隠すと、別のアプリに当てたとき黙って0件＝合格になる）。
## この章の前提

この章の5項目は、すべて**認可サーバ**（利用者を確かめ、引換券を発行する側）の振る舞いに
ついて求めている。対象アプリがその役目を自分で担っていない場合、5項目とも
**「合格（該当機能なし）」**とする。ただし**任せ先を名指しできること**を条件とする。
「たぶん任せている」で済ませない。

**例外は 10.4.4 である。** どの受け渡し方式を有効にするかは、任せ先の設定として
**対象アプリの持ち主が決められる**。したがって該当機能なしにせず、設定を見て判定する。

【認可サーバを自分で担っているかを調べる命令】（対象の一覧を作る命令）

```
grep -rnoiE 'authorization_code|/oauth/authorize|/oauth/token|client_secret|redirect_uri|grant_type' --include='*.js' --include='*.mjs' --include='*.sql' . | grep -v node_modules
```

### v5.0.0-10.4.1

- **原文**: Verify that the authorization server validates redirect URIs based on a client-specific allowlist of pre-registered URIs using exact string comparison.
- **日本語**: 認可サーバが、戻り先の URL を、あらかじめ登録した一覧と**完全一致**で照合すること。
- **判定のしかた**: 読む
- **見る場所**: 【認可サーバを自分で担っているかを調べる命令】の出力に挙がった箇所。
- **合格基準**: 対象アプリが認可サーバを担っている場合、戻り先の照合が完全一致であること。担っていない場合は、任せ先を名指しできることをもって「合格（該当機能なし）」とする。
- **該当しない条件**: 対象アプリが認可サーバを担っていない場合。
- **根拠として出すもの**: 命令の出力と、任せ先を特定できる箇所のファイル名と行番号。

### v5.0.0-10.4.2

- **原文**: Verify that, if the authorization server returns the authorization code in the authorization response, it can be used only once for a token request. For the second valid request with an authorization code that has already been used to issue an access token, the authorization server must reject a token request and revoke any issued tokens related to the authorization code.
- **日本語**: 認可サーバが発行する引換のための符号を、一度しか使えないようにすること。二度目の要求は断り、その符号で出した引換券も無効にすること。
- **判定のしかた**: 読む
- **見る場所**: 10.4.1 と同じ命令の出力。
- **合格基準**: 10.4.1 と同じ形で判定する。担っていなければ任せ先を名指しできることをもって「合格（該当機能なし）」。
- **該当しない条件**: 対象アプリが認可サーバを担っていない場合。
- **根拠として出すもの**: 10.4.1 と同じ。

### v5.0.0-10.4.3

- **原文**: Verify that the authorization code is short-lived. The maximum lifetime can be up to 10 minutes for L1 and L2 applications and up to 1 minute for L3 applications.
- **日本語**: 引換のための符号の有効期間を短くすること（L1 では最長10分）。
- **判定のしかた**: 読む
- **見る場所**: 10.4.1 と同じ命令の出力。
- **合格基準**: 10.4.1 と同じ形で判定する。
- **該当しない条件**: 対象アプリが認可サーバを担っていない場合。
- **根拠として出すもの**: 10.4.1 と同じ。

### v5.0.0-10.4.4

- **原文**: Verify that for a given client, the authorization server only allows the usage of grants that this client needs to use. Note that the grants 'token' (Implicit flow) and 'password' (Resource Owner Password Credentials flow) must no longer be used.
- **日本語**: その利用先が必要とする受け渡し方式だけを有効にすること。`token`（暗黙の流れ）と `password`（利用者の合言葉を直接渡す流れ）は、もう使ってはならない。
- **判定のしかた**: 読む
- **見る場所**: 経緯の記録のうち、ログインの仕組みの設定について書いた箇所。次の命令で絞る。

  ```
  grep -rlniE 'provider|ログイン方法|認証.?設定|grant|password|OAuth|Google' docs/ *.md
  ```

- **合格基準**: 次の2つをどちらも満たすこと。片方でも欠ければ不合格。記録が無ければ**判定不能**。
  1. 利用者の合言葉を直接渡す受け渡し方式が、**無効**になっていることが記録から分かる
  2. 暗黙の流れ（引換券を URL に載せて返す方式）を使っていないことが、コードまたは記録から分かる
- **該当しない条件**: 無い。
- **根拠として出すもの**: 1と2それぞれについて、ファイル名と行番号。

### v5.0.0-10.4.5

- **原文**: Verify that the authorization server mitigates refresh token replay attacks for public clients, preferably using sender-constrained refresh tokens, i.e., Demonstrating Proof of Possession (DPoP) or Certificate-Bound Access Tokens using mutual TLS (mTLS). For L1 and L2 applications, refresh token rotation may be used. If refresh token rotation is used, the authorization server must invalidate the refresh token after usage, and revoke all refresh tokens for that authorization if an already used and invalidated refresh token is provided.
- **日本語**: 認可サーバが、引換券の入れ替え用の符号の使い回し攻撃を防ぐこと。L1 では入れ替えのたびに作り直す方式でもよい。その場合、使い終わった符号は無効にし、使い回しが来たらその利用者の符号を全部無効にすること。
- **判定のしかた**: 読む
- **見る場所**: 10.4.1 と同じ命令の出力。
- **合格基準**: 10.4.1 と同じ形で判定する。
- **該当しない条件**: 対象アプリが認可サーバを担っていない場合。
- **根拠として出すもの**: 10.4.1 と同じ。
