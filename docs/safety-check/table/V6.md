# 固定表 — V6 認証（Authentication）

OWASP ASVS 5.0.0 の L1 のうち、章 V6 に属する **13項目**。項目は公式データ
（`../asvs-5.0.0-l1.csv`）と1対1で対応し、追加・削除・統合をしない。

判定のしかたは `機械`（実行する命令が確定しているもの）か `読む`（見る場所が確定している
もの）のどちらか。どちらの命令も、**対象アプリの置き場所の最上位で `bash` で実行する**。

出典: OWASP Application Security Verification Standard 5.0.0 (CC BY-SA 4.0)。
日本語は原文からの訳で、訳の責任はこの置き場所にある（`../../adr/0004` 参照）。

## この章の共通の但し書き

- **命令には3つの種類があり、出力が0件のときの意味が逆になる。** どれに当たるかを各項目の
  「命令の種類」に書く。書いていない命令は使わない。
  - **危険な書き方を探す命令**: 0件なら**合格**。探した書き方をしていない、という意味になる
  - **備えを探す命令**: 0件なら**不合格**。在るべきものが無い、という意味になる
  - **対象の一覧を作る命令**: 0件なら**判定不能**。対象が無いのか、命令が対象アプリの書き方と
    合っていないのかを区別できないため（`../../adr/0002`・`../../adr/0006`）
- **命令の出力に紛らわしい行が出たときは、その行を読む。** 本番の画面から到達できない
  試験専用の道具だと確かめられた場合に限り、その行を数に入れない。確かめられなければ
  数に入れる。**読まずに除外しない。読んだ行はすべて、確かめた結果とともに判定結果に残す。
  出力の一部を無記録で落とさない。**
- **命令は対象アプリの置き場所の最上位で `bash` で実行し、表に書いたとおりに実行する。**
  省略や追加をしない。探す範囲に対象アプリ固有の置き場所の名前を書かない。失敗を
  `2>/dev/null` で隠さない（隠すと、別のアプリに当てたとき黙って0件＝合格になる）。


### パスワードの8項目（6.2.1〜6.2.8）に共通の前提

アプリの画面にパスワード入力が無くても、それだけでは「該当しない」と言えない。
**ログインの仕組みの側がパスワードでのログインを受け付けるかどうか**が分からないかぎり、
画面を通さずに直接ログインされる道が**残っているかどうかも分からない**。分からないものを
「無い」として扱わない。

したがって次の2つをどちらも満たすときだけ「該当しない」と扱い、片方でも欠ければ
**判定不能**とする。

1. 【パスワード検索】の出力が0件であること（紛らわしい行の扱いは上記に従う）
2. **ログインの仕組みの側がパスワードでのログインを受け付けない**ことが、経緯の記録に
   書かれていること

【パスワード検索】

```
grep -rnoiE 'signInWithPassword|signUp\(|resetPasswordForEmail|updateUser\(|type=.?password' --include='*.js' --include='*.mjs' --include='*.html' . | grep -v node_modules
```

【記録検索】（上記2を確かめる）

```
grep -rlniE 'パスワード|password|ログイン方法|Google.?のみ|サインアップ|signup|認証.?設定' docs/ *.md 2>/dev/null
```

### v5.0.0-6.1.1

- **原文**: Verify that application documentation defines how controls such as rate limiting, anti-automation, and adaptive response, are used to defend against attacks such as credential stuffing and password brute force. The documentation must make clear how these controls are configured and prevent malicious account lockout.
- **日本語**: 総当たりや使い回しパスワードでの侵入に対する守り（回数制限・自動化対策・状況に応じた対応）を、どう使っているかが文書に定められていること。設定の内容と、正規の利用者を締め出さない仕組みが、文書から分かること。
- **判定のしかた**: 読む
- **見る場所**: 次の命令で挙がった文書。0件なら経緯の記録の全ファイル。

  ```
  grep -rlniE '回数制限|レート制限|rate.?limit|総当たり|brute|締め出し|ロックアウト|lockout' docs/ *.md 2>/dev/null
  ```

- **合格基準**: 挙がった文書のどれかに、**①ログインへの総当たりをどう防いでいるか**と、**②正規の利用者が締め出されないようにする仕組み**の両方が書かれていること。回数制限の仕組みが存在するだけで、それがログインを守るものだと書かれていなければ不合格ではなく**判定不能**とする（記録が欠けている）。
- **該当しない条件**: 無い。ログインを持たないアプリであれば、その旨が記録にあることをもって合格とする。
- **根拠として出すもの**: 該当箇所のファイル名と行番号。無い場合は、検索した命令とその出力。

### v5.0.0-6.4.1

- **原文**: Verify that system generated initial passwords or activation codes are securely randomly generated, follow the existing password policy, and expire after a short period of time or after they are initially used. These initial secrets must not be permitted to become the long term password.
- **日本語**: 仕組みが発行する初期パスワードや有効化コードが、安全な乱数で作られ、短い期間で、あるいは一度使われたら失効すること。それがそのまま長く使われるパスワードになってはならない。
- **判定のしかた**: 読む
- **見る場所**: 次の命令の出力に挙がった箇所。

  ```
  grep -rnoiE 'gen_random_bytes|randomUUID|crypto\.getRandomValues|invitation|activation|初期パスワード' --include='*.sql' --include='*.js' --include='*.mjs' . | grep -v node_modules
  ```

- **合格基準**: 発行される初期パスワードまたは有効化コードについて、次の3つをすべて満たすこと。1つでも欠ければ不合格。
  1. 安全な乱数で作られている（言語や仕組みが用意した暗号用の乱数を使っている。時刻や連番でない）
  2. 有効期限がある
  3. 一度使われたら二度目は通らない
- **該当しない条件**: 仕組みが発行する初期パスワードも有効化コードも存在しない場合（上の命令の出力が0件で、かつ記録にもその記述が無い場合）。
- **根拠として出すもの**: 3つそれぞれについて、ファイル名と行番号。
