# 固定表 — V3 ブラウザ側の安全（Web Frontend Security）

OWASP ASVS 5.0.0 の L1 のうち、章 V3 に属する **8項目**。項目は公式データ
（`../asvs-5.0.0-l1.csv`）と1対1で対応し、追加・削除・統合をしない。

判定のしかたは `機械`（実行する命令が確定しているもの）か `読む`（見る場所が確定している
もの）のどちらか。どちらの命令も、**対象アプリの置き場所の最上位で `bash` で実行する**。

出典: OWASP Application Security Verification Standard 5.0.0 (CC BY-SA 4.0)。
日本語は原文からの訳で、訳の責任はこの置き場所にある（`../../adr/0004` 参照）。

## この章の共通の但し書き

- **命令には3つの種類があり、出力が0件のときの意味が逆になる。** どれに当たるかを各項目の
  「命令の種類」に書く。書いていない命令は使わない。
  - **危険な書き方を探す命令**: 0件なら**合格**。探した書き方をしていない、という意味になる
  - **備えを探す命令**: 0件なら**不合格**。在るべきものが無い、という意味になる
  - **対象の一覧を作る命令**: 0件なら**判定不能**。対象が無いのか、命令が対象アプリの書き方と
    合っていないのかを区別できないため（`../../adr/0002`・`../../adr/0006`）
- **命令の出力に紛らわしい行が出たときは、その行を読む。** 本番の画面から到達できない
  試験専用の道具だと確かめられた場合に限り、その行を数に入れない。確かめられなければ
  数に入れる。**読まずに除外しない。読んだ行はすべて、確かめた結果とともに判定結果に残す。
  出力の一部を無記録で落とさない。**
- **命令は対象アプリの置き場所の最上位で `bash` で実行し、表に書いたとおりに実行する。**
  省略や追加をしない。探す範囲に対象アプリ固有の置き場所の名前を書かない。失敗を
  `2>/dev/null` で隠さない（隠すと、別のアプリに当てたとき黙って0件＝合格になる）。
- この章には、**公開されている画面に実際に取りに行って応答の見出しを見る**項目がある。
  対象アプリが公開されていない場合、それらは判定不能とする。応答を見るだけで、
  画面を操作したり値を送り込んだりはしない。

【応答の見出しを取る命令】（`<URL>` は対象アプリの入口）

```
curl -sS -I -L --max-time 30 <URL>
```

### v5.0.0-3.2.1

- **原文**: Verify that security controls are in place to prevent browsers from rendering content or functionality in HTTP responses in an incorrect context (e.g., when an API, a user-uploaded file or other resource is requested directly). Possible controls could include: not serving the content unless HTTP request header fields (such as Sec-Fetch-\*) indicate it is the correct context, using the sandbox directive of the Content-Security-Policy header field or using the attachment disposition type in the Content-Disposition header field.
- **日本語**: 利用者が上げたファイルなどを直接開かれたとき、ブラウザがそれを想定外の形で解釈しないようにすること。
- **判定のしかた**: 読む
- **見る場所**: 次の命令の出力に挙がった箇所と、保管場所の設定。

  ```
  grep -rnoiE 'Content-Disposition|sandbox|public *= *(true|false)|public *: *(true|false)|createSignedUrl|getPublicUrl|storage\.buckets' --include='*.js' --include='*.mjs' --include='*.sql' --include='*.toml' . | grep -v node_modules
  ```

- **合格基準**: 利用者が上げたファイルについて、次のいずれかを満たすこと。
  1. 誰でも開ける場所に置いておらず、その都度の許可が要る形で配っている
  2. 応答に「添付として扱う」指定が付いている
  3. 応答に、閉じ込めて表示する指定が付いている

  受け入れる形式が画像だけに限られていることも根拠に含めてよいが、それ単独では足りない。
- **該当しない条件**: 利用者がファイルを上げる機能が無い場合。
- **根拠として出すもの**: 満たしたものの番号と、そのファイル名と行番号。

### v5.0.0-3.2.2

- **原文**: Verify that content intended to be displayed as text, rather than rendered as HTML, is handled using safe rendering functions (such as createTextNode or textContent) to prevent unintended execution of content such as HTML or JavaScript.
- **日本語**: 文字として見せるつもりの内容を、HTML として解釈させない入れ方で画面に出すこと。
- **判定のしかた**: 読む
- **見る場所**: 次の命令の出力に挙がった箇所。ここに挙がらない場所は見ない。

  ```
  grep -rnoE 'innerHTML|outerHTML|insertAdjacentHTML|document\.write' --include='*.js' --include='*.mjs' --include='*.html' . | grep -v node_modules
  ```

- **合格基準**: 利用者が入力した値を画面に出している箇所が、すべて安全な入れ方（`textContent` / `createTextNode` など）であること。1件でも HTML として入れている箇所があれば不合格。
- **該当しない条件**: 無い。
- **根拠として出すもの**: 安全な入れ方の件数と、HTML として入れている箇所の有無。ファイル名と行番号。

### v5.0.0-3.3.1

- **原文**: Verify that cookies have the 'Secure' attribute set, and if the '\__Host-' prefix is not used for the cookie name, the '__Secure-' prefix must be used for the cookie name.
- **日本語**: ブラウザに保存する小さな記録（クッキー）に、暗号化された通信でしか送らない指定を付けること。名前にも決められた接頭辞を付けること。
- **判定のしかた**: 読む
- **見る場所**: 次の命令の出力に挙がった箇所。ここに挙がらない場所は見ない。

  ```
  grep -rnoiE 'Set-Cookie|document\.cookie|cookieStore' --include='*.js' --include='*.mjs' . | grep -v node_modules
  ```

- **合格基準**: 挙がった箇所に現れるクッキーすべてが、次の2つをどちらも満たすこと。片方でも欠ければ不合格。
  1. 暗号化された通信でしか送らない指定（`Secure`）が付いている
  2. 名前が `__Host-` で始まる。始まらない場合は `__Secure-` で始まる
- **該当しない条件**: クッキーを使っていない場合（命令の出力が0件）。このときは「合格（該当機能なし）」とする。
- **根拠として出すもの**: 命令の出力そのものと、挙がった箇所を読んだ結果。

### v5.0.0-3.4.1

- **原文**: Verify that a Strict-Transport-Security header field is included on all responses to enforce an HTTP Strict Transport Security (HSTS) policy. A maximum age of at least 1 year must be defined, and for L2 and up, the policy must apply to all subdomains as well.
- **日本語**: すべての応答に「以後この場所へは必ず暗号化された通信で来ること」を指示する見出しを付けること。期間は1年以上とすること。
- **判定のしかた**: 機械
- **命令の種類**: 備えを探す命令
- **合格基準**: 【応答の見出しを取る命令】の出力に `strict-transport-security` があり、その `max-age` が **31536000（1年）以上**であること。見出しが無ければ不合格。
- **該当しない条件**: 無い。対象アプリが公開されておらず命令を実行できない場合は、該当しないのではなく**判定不能**とする。
- **根拠として出すもの**: 命令の出力のうち、該当する見出しの行。無い場合は「0件」と記録する。

### v5.0.0-3.4.2

- **原文**: Verify that the Cross-Origin Resource Sharing (CORS) Access-Control-Allow-Origin header field is a fixed value by the application, or if the Origin HTTP request header field value is used, it is validated against an allowlist of trusted origins. When 'Access-Control-Allow-Origin: *' needs to be used, verify that the response does not include any sensitive information.
- **日本語**: 他の場所からの読み取りを許す見出しの値を、アプリが決めた固定の値にするか、許す一覧と照らして確かめること。誰にでも許す指定を使うなら、その応答に大事な情報を含めないこと。
- **判定のしかた**: 読む
- **見る場所**: 次の命令の出力に挙がった箇所。

  ```
  grep -rnoiE 'Access-Control-Allow-Origin|Access-Control-Allow' --include='*.js' --include='*.mjs' . | grep -v node_modules
  ```

- **合格基準**: 許す相手の値が、**固定の値**であるか、**受け取った値を一覧や決まった形と照らして確かめてから返している**こと。受け取った値をそのまま返している箇所があれば不合格。誰にでも許す指定（`*`）を使っている場合は、その応答に大事な情報が含まれないことを確かめる。
- **該当しない条件**: 他の場所からの読み取りを許す見出しを一切返していない場合。このときは「合格（該当機能なし）」とする。
- **根拠として出すもの**: 値を決めている箇所のファイル名と行番号と、その判断。

### v5.0.0-3.5.1

- **原文**: Verify that, if the application does not rely on the CORS preflight mechanism to prevent disallowed cross-origin requests to use sensitive functionality, these requests are validated to ensure they originate from the application itself. This may be done by using and validating anti-forgery tokens or requiring extra HTTP header fields that are not CORS-safelisted request-header fields. This is to defend against browser-based request forgery attacks, commonly known as cross-site request forgery (CSRF).
- **日本語**: 大事な操作への要求が、本当にこのアプリの画面から出たものかを確かめること。他の場所に置かれた罠から勝手に送られる攻撃を防ぐため。
- **判定のしかた**: 読む
- **見る場所**: 次の命令の出力に挙がった箇所。

  ```
  grep -rnoiE 'Authorization|Bearer|csrf|anti.?forgery|X-Requested-With|SameSite|Sec-Fetch' --include='*.js' --include='*.mjs' . | grep -v node_modules
  ```

- **合格基準**: 大事な操作を扱う経路すべてが、次のいずれかを満たすこと。
  1. 決まった見出し（`Authorization` など、他の場所から勝手には付けられないもの）を必須にしている
  2. その画面でしか作れない使い捨ての値を、要求に添えさせて確かめている
  3. 要求の出どころを示す見出しを確かめている

  ブラウザに保存した記録（クッキー）だけで利用者を見分けていて、上のいずれも無ければ不合格。
- **該当しない条件**: 無い。
- **根拠として出すもの**: 満たしたものの番号と、そのファイル名と行番号。大事な操作を扱う経路が、すべてそこを通ることを示す根拠も。

### v5.0.0-3.5.2

- **原文**: Verify that, if the application relies on the CORS preflight mechanism to prevent disallowed cross-origin use of sensitive functionality, it is not possible to call the functionality with a request which does not trigger a CORS-preflight request. This may require checking the values of the 'Origin' and 'Content-Type' request header fields or using an extra header field that is not a CORS-safelisted header-field.
- **日本語**: 他の場所からの要求を、事前の問い合わせで止める仕組みに頼っている場合、その事前の問い合わせを起こさない形では呼べないようにすること。
- **判定のしかた**: 読む
- **見る場所**: 次の命令の出力に挙がった箇所。ここに挙がらない場所は見ない。

  ```
  grep -rnoiE 'Content-Type|Authorization|request\.headers\.get|headers\[' --include='*.js' --include='*.mjs' . | grep -v node_modules
  ```

- **合格基準**: 大事な操作が、**事前の問い合わせを必ず起こす形でしか呼べない**こと。次の2つをどちらも満たすこと。
  1. 他の場所から勝手には付けられない見出し（`Authorization` など）を必須にしている
  2. その見出しが無い要求を、中身を処理する前に断っている

  見出しを必須にしておらず、単純な送信でも呼べるなら不合格。
- **該当しない条件**: 無い。
- **根拠として出すもの**: 必須にしている見出しの名前と、それを確かめている箇所のファイル名と行番号。

### v5.0.0-3.5.3

- **原文**: Verify that HTTP requests to sensitive functionality use appropriate HTTP methods such as POST, PUT, PATCH, or DELETE, and not methods defined by the HTTP specification as "safe" such as HEAD, OPTIONS, or GET. Alternatively, strict validation of the Sec-Fetch-* request header fields can be used to ensure that the request did not originate from an inappropriate cross-origin call, a navigation request, or a resource load (such as an image source) where this is not expected.
- **日本語**: 変更をともなう操作に、読み取り用の送り方（`GET` など）を使わないこと。
- **判定のしかた**: 機械
- **命令の種類**: 対象の一覧を作る命令
- **合格基準**: 次の命令の出力が**1件以上**あり（0件なら判定不能）、そのうち `GET` を受けている経路のすべてが読み取りだけであること。**変更をともなう操作（作る・直す・消す）が `GET` で呼べる箇所が1件でもあれば不合格**。

  ```
  grep -rnoE "request\.method *=== *'[A-Z]+'|method: *'[A-Z]+'" --include='*.js' --include='*.mjs' . | grep -v node_modules
  ```

- **該当しない条件**: 無い。
- **根拠として出すもの**: 送り方ごとの件数と、変更をともなう操作が `GET` で呼べないことを示す根拠。
