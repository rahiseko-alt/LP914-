# 固定表 — V5 ファイルの取り扱い（File Handling）

OWASP ASVS 5.0.0 の L1 のうち、章 V5 に属する **4項目**。項目は公式データ
（`../asvs-5.0.0-l1.csv`）と1対1で対応し、追加・削除・統合をしない。

判定のしかたは `機械`（実行する命令が確定しているもの）か `読む`（見る場所が確定している
もの）のどちらか。どちらの命令も、**対象アプリの置き場所の最上位で `bash` で実行する**。

出典: OWASP Application Security Verification Standard 5.0.0 (CC BY-SA 4.0)。
日本語は原文からの訳で、訳の責任はこの置き場所にある（`../../adr/0004` 参照）。

## この章の共通の但し書き

- **命令には3つの種類があり、出力が0件のときの意味が逆になる。** どれに当たるかを各項目の
  「命令の種類」に書く。書いていない命令は使わない。
  - **危険な書き方を探す命令**: 0件なら**合格**。探した書き方をしていない、という意味になる
  - **備えを探す命令**: 0件なら**不合格**。在るべきものが無い、という意味になる
  - **対象の一覧を作る命令**: 0件なら**判定不能**。対象が無いのか、命令が対象アプリの書き方と
    合っていないのかを区別できないため（`../../adr/0002`・`../../adr/0006`）
- **命令の出力に紛らわしい行が出たときは、その行を読む。** 本番の画面から到達できない
  試験専用の道具だと確かめられた場合に限り、その行を数に入れない。確かめられなければ
  数に入れる。**読まずに除外しない。読んだ行はすべて、確かめた結果とともに判定結果に残す。
  出力の一部を無記録で落とさない。**
- **命令は対象アプリの置き場所の最上位で `bash` で実行し、表に書いたとおりに実行する。**
  省略や追加をしない。探す範囲に対象アプリ固有の置き場所の名前を書かない。失敗を
  `2>/dev/null` で隠さない（隠すと、別のアプリに当てたとき黙って0件＝合格になる）。
- この章は、**利用者がファイルを上げる機能があるかどうか**で分岐する。下の命令は
  **危険な書き方を探す命令ではなく、対象の一覧を作る命令**である。0件だったときは、
  「機能が無い」と「命令が対象アプリの書き方と合っていない」を区別できない。
  **0件だった場合は、経緯の記録にファイルを上げる機能が無いと書かれていることを確かめる。**
  書かれていれば4項目とも「合格（該当機能なし）」、書かれていなければ4項目とも**判定不能**。

【ファイルを受け取る箇所を調べる命令】（対象の一覧を作る命令）

```
grep -rnoiE 'upload|<input[^>]*type=.?file|FormData|Blob\(|storage\.from|storage\.buckets' --include='*.js' --include='*.mjs' --include='*.html' --include='*.sql' . | grep -v node_modules
```

### v5.0.0-5.2.1

- **原文**: Verify that the application will only accept files of a size which it can process without causing a loss of performance or a denial of service attack.
- **日本語**: 処理しきれない大きさのファイルを受け付けないこと。
- **判定のしかた**: 読む
- **見る場所**: 【ファイルを受け取る箇所を調べる命令】の出力に挙がった箇所と、次の命令の出力に挙がった箇所。この2つ以外は見ない。

  ```
  grep -rnoiE 'file_size_limit|maxFileSize|MAX_[A-Z_]*BYTES|size *[<>]=? *[0-9]' --include='*.js' --include='*.mjs' --include='*.sql' --include='*.toml' . | grep -v node_modules
  ```

- **合格基準**: 上限の大きさが**サーバ側または保管場所の設定で決まっていて、それを超えるものが弾かれる**こと。ブラウザ側にしか上限が無ければ不合格。数値が具体的に書かれていること。
- **該当しない条件**: 利用者がファイルを上げる機能が無い場合。
- **根拠として出すもの**: 上限の数値と、それを決めている箇所のファイル名と行番号。サーバ側であることを示す根拠も。

### v5.0.0-5.2.2

- **原文**: Verify that when the application accepts a file, either on its own or within an archive such as a zip file, it checks if the file extension matches an expected file extension and validates that the contents correspond to the type represented by the extension. This includes, but is not limited to, checking the initial 'magic bytes', performing image re-writing, and using specialized libraries for file content validation. For L1, this can focus just on files which are used to make specific business or security decisions. For L2 and up, this must apply to all files being accepted.
- **日本語**: 受け取ったファイルの種類が想定どおりかを確かめ、さらに**中身が名乗っている種類と一致している**ことを確かめること（先頭の数バイトを見る、など）。
- **判定のしかた**: 読む
- **見る場所**: 【ファイルを受け取る箇所を調べる命令】の出力に挙がった箇所。
- **合格基準**: まず、受け取るファイルが**判断に使われるもの**かどうかを決める。原文の「For L1, this can focus just on files which are used to make specific business or security decisions」に従い、L1 で必ず確かめるのは**判断に使われるファイル**に限る。中身を見せるだけ・保存するだけのファイルは、この項目の対象から外してよい（外した理由を判定結果に書くこと）。

  対象となるファイルについて、次の2つをどちらも満たすこと。片方でも欠ければ不合格。
  1. 受け付ける種類が**許す一覧**で決まっていて、その確認が**サーバ側または保管場所の設定**で行われていること
  2. **中身が名乗っている種類と一致しているか**を確かめていること（先頭の数バイトを見る、画像として読み直す、等）。この確認が**ブラウザ側でしか行われていない場合は不合格**とする。ブラウザを通さず直接送れば迂回できるため、守りとして成立しない（2.2.2 と同じ理由）

  対象から外したファイルについては、1 と 2 の実際の状態を判定結果に**事実として記録する**。判定には算入しないが、記録は省かない。
- **該当しない条件**: 利用者がファイルを上げる機能が無い場合。
- **根拠として出すもの**: 1と2それぞれのファイル名と行番号。2 がどこで動くか（サーバ側かブラウザ側か）も。

### v5.0.0-5.3.1

- **原文**: Verify that files uploaded or generated by untrusted input and stored in a public folder, are not executed as server-side program code when accessed directly with an HTTP request.
- **日本語**: 利用者が上げたファイルが、直接開かれたときにサーバ側の命令として実行されないこと。
- **判定のしかた**: 読む
- **見る場所**: 保管場所の設定と、配り方を決めている箇所。

  ```
  grep -rnoiE "public *= *(true|false)|storage\.buckets|createSignedUrl|getPublicUrl" --include='*.sql' --include='*.js' --include='*.mjs' --include='*.toml' . | grep -v node_modules
  ```

- **合格基準**: 次のいずれかを満たすこと。
  1. 保管場所が誰でも開ける設定になっていない
  2. 保管場所が命令を実行しない仕組み（ファイルを置くだけの保管サービス）である

  アプリのコードと同じ場所にファイルを置いていて、そこが命令を実行しうるなら不合格。
- **該当しない条件**: 利用者がファイルを上げる機能が無い場合。
- **根拠として出すもの**: 満たしたものの番号と、そのファイル名と行番号。

### v5.0.0-5.3.2

- **原文**: Verify that when the application creates file paths for file operations, instead of user-submitted filenames, it uses internally generated or trusted data, or if user-submitted filenames or file metadata must be used, strict validation and sanitization must be applied. This is to protect against path traversal, local or remote file inclusion (LFI, RFI), and server-side request forgery (SSRF) attacks.
- **日本語**: ファイルの置き場所を決めるとき、利用者が付けた名前をそのまま使わず、こちらで作った値を使うこと。使う必要があるなら厳しく確かめること。
- **判定のしかた**: 読む
- **見る場所**: 置き場所を組み立てている箇所。

  ```
  grep -rnoiE 'storagePath|storage_path|buildPath|filePath|filename|\.name\b' --include='*.js' --include='*.mjs' --include='*.sql' . | grep -v node_modules
  ```

- **合格基準**: 置き場所を組み立てるのに使う値が、**すべてこちらで作った値か、形を確かめた値**であること。利用者が付けたファイル名がそのまま混ざっていれば不合格。上の階層へ戻る記号（`..`）が入りうる作りになっていないこと。
- **該当しない条件**: 利用者がファイルを上げる機能が無い場合。
- **根拠として出すもの**: 組み立てている箇所のファイル名と行番号と、使っている値それぞれの出どころ。
