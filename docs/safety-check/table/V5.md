# 固定表 — V5 ファイルの取り扱い（File Handling）

OWASP ASVS 5.0.0 の L1 のうち、章 V5 に属する **4項目**。項目は公式データ
（`../asvs-5.0.0-l1.csv`）と1対1で対応し、追加・削除・統合をしない。

判定のしかたは `機械`（実行する命令が確定しているもの）か `読む`（見る場所が確定している
もの）のどちらか。どちらの命令も、**対象アプリの置き場所の最上位で `bash` で実行する**。

出典: OWASP Application Security Verification Standard 5.0.0 (CC BY-SA 4.0)。
日本語は原文からの訳で、訳の責任はこの置き場所にある（`../../adr/0004` 参照）。

## この章の共通の但し書き

- **命令が何も見つけられなかったときは、合格ではなく判定不能とする**（`../../adr/0002`）。
- この章は、**利用者がファイルを上げる機能があるかどうか**で分岐する。無ければ4項目とも
  「合格（該当機能なし）」。あるなら1件ずつ判定する。

【ファイルを受け取る箇所を調べる命令】

```
grep -rnoiE 'upload|<input[^>]*type=.?file|FormData|Blob\(|storage\.from|bucket' worker/src/ backend/js/ src/ supabase/migrations/*.sql 2>/dev/null | head -30
```

---

### v5.0.0-5.2.1

- **原文**: Verify that the application will only accept files of a size which it can process without causing a loss of performance or a denial of service attack.
- **日本語**: 処理しきれない大きさのファイルを受け付けないこと。
- **判定のしかた**: 読む
- **見る場所**: 【ファイルを受け取る箇所を調べる命令】の出力に挙がった箇所と、保管場所の設定。
- **合格基準**: 上限の大きさが**サーバ側または保管場所の設定で決まっていて、それを超えるものが弾かれる**こと。ブラウザ側にしか上限が無ければ不合格。数値が具体的に書かれていること。
- **該当しない条件**: 利用者がファイルを上げる機能が無い場合。
- **根拠として出すもの**: 上限の数値と、それを決めている箇所のファイル名と行番号。サーバ側であることを示す根拠も。

---

### v5.0.0-5.2.2

- **原文**: Verify that when the application accepts a file, either on its own or within an archive such as a zip file, it checks if the file extension matches an expected file extension and validates that the contents correspond to the type represented by the extension. This includes, but is not limited to, checking the initial 'magic bytes', performing image re-writing, and using specialized libraries for file content validation.
- **日本語**: 受け取ったファイルの種類が想定どおりかを確かめ、さらに**中身が名乗っている種類と一致している**ことを確かめること（先頭の数バイトを見る、など）。
- **判定のしかた**: 読む
- **見る場所**: 【ファイルを受け取る箇所を調べる命令】の出力に挙がった箇所。
- **合格基準**: 次の2つをどちらも満たすこと。片方でも欠ければ不合格。
  1. 受け付ける種類が**許す一覧**で決まっていること
  2. **中身が名乗っている種類と一致しているか**を確かめていること（先頭の数バイトを見る、画像として読み直す、等）

  2 がブラウザ側でしか行われていない場合は、その事実を判定結果に明記したうえで合格としてよい。ただし**明記しない合格は認めない**。
- **該当しない条件**: 利用者がファイルを上げる機能が無い場合。
- **根拠として出すもの**: 1と2それぞれのファイル名と行番号。2 がどこで動くか（サーバ側かブラウザ側か）も。

### v5.0.0-5.3.1

- **原文**: Verify that files uploaded or generated by untrusted input and stored in a public folder, are not executed as server-side program code when accessed directly with an HTTP request.
- **日本語**: 利用者が上げたファイルが、直接開かれたときにサーバ側の命令として実行されないこと。
- **判定のしかた**: 読む
- **見る場所**: 保管場所の設定と、配り方を決めている箇所。

  ```
  grep -rnoiE "public *= *(true|false)|storage\.buckets|createSignedUrl|getPublicUrl" supabase/migrations/*.sql worker/src/ backend/js/ 2>/dev/null
  ```

- **合格基準**: 次のいずれかを満たすこと。
  1. 保管場所が誰でも開ける設定になっていない
  2. 保管場所が命令を実行しない仕組み（ファイルを置くだけの保管サービス）である

  アプリのコードと同じ場所にファイルを置いていて、そこが命令を実行しうるなら不合格。
- **該当しない条件**: 利用者がファイルを上げる機能が無い場合。
- **根拠として出すもの**: 満たしたものの番号と、そのファイル名と行番号。

---

### v5.0.0-5.3.2

- **原文**: Verify that when the application creates file paths for file operations, instead of user-submitted filenames, it uses internally generated or trusted data, or if user-submitted filenames or file metadata must be used, strict validation and sanitization must be applied.
- **日本語**: ファイルの置き場所を決めるとき、利用者が付けた名前をそのまま使わず、こちらで作った値を使うこと。使う必要があるなら厳しく確かめること。
- **判定のしかた**: 読む
- **見る場所**: 置き場所を組み立てている箇所。

  ```
  grep -rnoiE 'buildAssetPath|path *=|storagePath|\.name\b|filename' backend/js/supabase-storage.js worker/src/ 2>/dev/null | head -20
  ```

- **合格基準**: 置き場所を組み立てるのに使う値が、**すべてこちらで作った値か、形を確かめた値**であること。利用者が付けたファイル名がそのまま混ざっていれば不合格。上の階層へ戻る記号（`..`）が入りうる作りになっていないこと。
- **該当しない条件**: 利用者がファイルを上げる機能が無い場合。
- **根拠として出すもの**: 組み立てている箇所のファイル名と行番号と、使っている値それぞれの出どころ。
