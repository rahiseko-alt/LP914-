# 固定表 — V11 暗号（Cryptography）

OWASP ASVS 5.0.0 の L1 のうち、章 V11 に属する **3項目**。項目は公式データ
（`../asvs-5.0.0-l1.csv`）と1対1で対応し、追加・削除・統合をしない。

判定のしかたは `機械`（実行する命令が確定しているもの）か `読む`（見る場所が確定している
もの）のどちらか。どちらの命令も、**対象アプリの置き場所の最上位で `bash` で実行する**。

出典: OWASP Application Security Verification Standard 5.0.0 (CC BY-SA 4.0)。
日本語は原文からの訳で、訳の責任はこの置き場所にある（`../../adr/0004` 参照）。

## この章の共通の但し書き

- **命令には3つの種類があり、出力が0件のときの意味が逆になる。** どれに当たるかを各項目の
  「命令の種類」に書く。書いていない命令は使わない。
  - **危険な書き方を探す命令**: 0件なら**合格**。探した書き方をしていない、という意味になる
  - **備えを探す命令**: 0件なら**不合格**。在るべきものが無い、という意味になる
  - **対象の一覧を作る命令**: 0件なら**判定不能**。対象が無いのか、命令が対象アプリの書き方と
    合っていないのかを区別できないため（`../../adr/0002`・`../../adr/0006`）
- **命令の出力に紛らわしい行が出たときは、その行を読む。** 本番の画面から到達できない
  試験専用の道具だと確かめられた場合に限り、その行を数に入れない。確かめられなければ
  数に入れる。**読まずに除外しない。読んだ行はすべて、確かめた結果とともに判定結果に残す。
  出力の一部を無記録で落とさない。**
- **命令は対象アプリの置き場所の最上位で `bash` で実行し、表に書いたとおりに実行する。**
  省略や追加をしない。探す範囲に対象アプリ固有の置き場所の名前を書かない。失敗を
  `2>/dev/null` で隠さない（隠すと、別のアプリに当てたとき黙って0件＝合格になる）。

【暗号の使い方を調べる命令】（対象の一覧を作る命令）

```
grep -rnoiE 'crypto|cipher|encrypt|decrypt|digest|hash|hmac|sign\(|createHash' --include='*.js' --include='*.mjs' --include='*.sql' . | grep -v node_modules
```

### v5.0.0-11.3.1

- **原文**: Verify that insecure block modes (e.g., ECB) and weak padding schemes (e.g., PKCS#1 v1.5) are not used.
- **日本語**: 安全でない暗号の使い方（ECB のような塊ごとの処理の仕方や、弱い詰め物の方式）を使っていないこと。
- **判定のしかた**: 機械
- **命令の種類**: 危険な書き方を探す命令
- **合格基準**: 次の命令の出力が**0件**であること。1件でも出れば不合格。

  ```
  grep -rnoiE '\bECB\b|createCipher\(|PKCS#?1[^_]|-----BEGIN RSA' --include='*.js' --include='*.mjs' --include='*.sql' . | grep -v node_modules
  ```

- **該当しない条件**: 対象アプリが自前で暗号化していない場合（【暗号の使い方を調べる命令】の出力に、暗号化を行う箇所が1つも無い場合）。このときは「合格（該当機能なし）」とする。
- **根拠として出すもの**: 命令の出力そのもの。該当なしとした場合は、暗号化を行う箇所が無いことを示す出力も。

### v5.0.0-11.3.2

- **原文**: Verify that only approved ciphers and modes such as AES with GCM are used.
- **日本語**: 認められた暗号方式（AES-GCM など）だけを使うこと。
- **判定のしかた**: 読む
- **見る場所**: 【暗号の使い方を調べる命令】の出力に挙がった箇所のうち、暗号化を行っているもの。ここに挙がらない場所は見ない。
- **合格基準**: 暗号化に使っている方式が、広く認められたもの（AES-GCM、ChaCha20-Poly1305 など）であること。独自に考えた方式や、古くて破られている方式を使っていれば不合格。
- **該当しない条件**: 対象アプリが自前で暗号化していない場合。このときは「合格（該当機能なし）」とする。
- **根拠として出すもの**: 使っている方式の名前と、そのファイル名と行番号。

### v5.0.0-11.4.1

- **原文**: Verify that only approved hash functions are used for general cryptographic use cases, including digital signatures, HMAC, KDF, and random bit generation. Disallowed hash functions, such as MD5, must not be used for any cryptographic purpose.
- **日本語**: 認められた要約の作り方（ハッシュ関数）だけを使うこと。MD5 のような認められていないものを、暗号としての用途に使わないこと。
- **判定のしかた**: 読む
- **見る場所**: 次の命令の出力に挙がった箇所と、【暗号の使い方を調べる命令】の出力。この2つ以外は見ない。
- **合格基準**: 次の命令の出力に挙がった箇所を読み、**暗号としての用途（合言葉の保存、署名、鍵の作成、乱数）に使われているものが0件**であること。1件でもあれば不合格。加えて、実際に使っている要約の作り方が認められたもの（SHA-256 以上）であること。

  ```
  grep -rnoiE "\bmd5\b|\bsha1\b|\bsha-1\b" --include='*.js' --include='*.mjs' --include='*.sql' . | grep -v node_modules
  ```

- **該当しない条件**: 無い。
- **根拠として出すもの**: 命令の出力そのもの。使っている要約の作り方の名前と、そのファイル名と行番号。
