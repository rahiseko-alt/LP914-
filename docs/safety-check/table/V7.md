# 固定表 — V7 セッション管理（Session Management）

OWASP ASVS 5.0.0 の L1 のうち、章 V7 に属する **6項目**。項目は公式データ
（`../asvs-5.0.0-l1.csv`）と1対1で対応し、追加・削除・統合をしない。

判定のしかたは `機械`（実行する命令が確定しているもの）か `読む`（見る場所が確定している
もの）のどちらか。どちらの命令も、**対象アプリの置き場所の最上位で `bash` で実行する**。

出典: OWASP Application Security Verification Standard 5.0.0 (CC BY-SA 4.0)。
日本語は原文からの訳で、訳の責任はこの置き場所にある（`../../adr/0004` 参照）。

## この章の共通の但し書き

- **命令が何も見つけられなかったときは、合格ではなく判定不能とする**（`../../adr/0002`）。
- **命令の出力に紛らわしい行が出たときは、その行を読む。** 本番の画面から到達できない
  試験専用の道具だと確かめられた場合に限り、その行を数に入れない。確かめられなければ
  数に入れる。**読まずに除外しない。**確かめた根拠（ファイル名と行番号）を判定結果に残す。
- ログインの仕組みを外部のサービスに任せている場合、**任せていること自体は不合格ではない**。
  ただし「任せているから大丈夫」で済ませない。**任せ先が記録で特定できること**を合格の
  条件に含め、任せ先の設定そのものが問われる項目では、その設定が記録にあるかを見る。
  記録に無ければ判定不能とする。

  【ログイン引換券の持ちかたを調べる命令】

  ```
  grep -rnoiE 'setSession|getSession|signOut|refreshSession|access_token|refresh_token|localStorage|sessionStorage|document\.cookie' --include='*.js' --include='*.mjs' . | grep -v node_modules | head -30
  ```

### v5.0.0-7.2.1

- **原文**: Verify that the application performs all session token verification using a trusted, backend service.
- **日本語**: ログイン引換券の検証を、すべて信頼できるサーバ側の仕組みで行うこと。
- **判定のしかた**: 読む
- **見る場所**: 共通の但し書きの命令の出力と、次の命令の出力。

  ```
  grep -rnoiE 'jwt|jose|jsonwebtoken|decode|atob' worker/src/ backend/js/ --include='*.js' --include='*.mjs'
  ```

- **合格基準**: ブラウザ側の JavaScript が、ログイン引換券の中身を自前で解いて「この人は誰か」を決めている箇所が無いこと。検証がサーバ側（データベースの仕組み、サーバで動く中継、ログインの仕組みを提供するサービス）で行われていることが、コードから追えること。`atob` などが出た場合は、その行を読み、ログイン引換券とは無関係の用途（画像の変換など）であると確かめる。
- **該当しない条件**: 無い。
- **根拠として出すもの**: 検証を行っている箇所のファイル名と行番号。命令で出た紛らわしい箇所については、無関係であると確かめた行番号。

### v5.0.0-7.2.2

- **原文**: Verify that the application uses either self-contained or reference tokens that are dynamically generated for session management, i.e. not using static API secrets and keys.
- **日本語**: ログイン状態の管理に、その都度作られるログイン引換券を使うこと。固定の秘密鍵や API キーを使い回さないこと。
- **判定のしかた**: 読む
- **見る場所**: 【ログイン引換券の持ちかたを調べる命令】の出力に挙がった箇所と、`.env.example` に相当する設定の見本。この2つ以外は見ない。
- **合格基準**: 利用者ごとの見分けに使っているものが、ログインのたびに作られるログイン引換券であること。固定の鍵を利用者の見分けに使っていないこと。ブラウザに固定の鍵を置いている場合、それが**公開してよい鍵**であり、それだけでは何も読めない（別にログイン状態が要る）ことが、コードまたは記録から分かること。
- **該当しない条件**: 無い。
- **根拠として出すもの**: ログイン引換券を受け取っている箇所と、固定の鍵の用途を示す箇所。ファイル名と行番号。

### v5.0.0-7.2.3

- **原文**: Verify that if reference tokens are used to represent user sessions, they are unique and generated using a cryptographically secure pseudo-random number generator (CSPRNG) and possess at least 128 bits of entropy.
- **日本語**: 引換券のようなログイン引換券を使う場合、それが重複せず、暗号用の乱数で作られ、128ビット以上の予測しにくさを持つこと。
- **判定のしかた**: 読む
- **見る場所**: 次の命令の出力に挙がった箇所。

  ```
  grep -rnoiE 'gen_random_bytes|randomUUID|getRandomValues|randomBytes|Math\.random' --include='*.js' --include='*.mjs' --include='*.sql' . | grep -v node_modules
  ```

- **合格基準**: 対象アプリ自身がログイン状態のログイン引換券を作っている箇所があれば、暗号用の乱数を使い、16バイト（128ビット）以上であること。`Math.random` のような予測しやすい乱数をログイン引換券に使っていないこと。
- **該当しない条件**: 対象アプリ自身がログイン状態のログイン引換券を作っていない場合（作成箇所が0件で、ログインを外部のサービスに任せていることが記録で特定できる場合）。このときは「合格（該当機能なし）」とする。
- **根拠として出すもの**: 命令の出力と、任せ先を特定できる記録のファイル名と行番号。

### v5.0.0-7.2.4

- **原文**: Verify that the application generates a new session token on user authentication, including re-authentication, and terminates the current session token.
- **日本語**: 利用者がログインしたとき（ログインし直したときも含む）に新しいログイン引換券を発行し、それまでのログイン引換券を終わらせること。
- **判定のしかた**: 読む
- **見る場所**: 【ログイン引換券の持ちかたを調べる命令】の出力に挙がった箇所と、次の命令で挙がった文書。この2つ以外は見ない。

  ```
  grep -rlniE 'ログアウト|signOut|ログイン状態|セッション|端末|失効|期限' docs/ *.md 2>/dev/null
  ```
- **合格基準**: ログインのたびにログイン引換券が入れ替わり、古いものが使えなくなることが、コードまたは記録から分かること。ログインを外部のサービスに任せている場合は、**その挙動が記録に書かれていること**をもって合格とする。任せ先の名前だけで挙動の記述が無ければ**判定不能**とする。
- **該当しない条件**: 無い。
- **根拠として出すもの**: 該当箇所のファイル名と行番号。無い場合は、検索した命令とその出力。

### v5.0.0-7.4.1

- **原文**: Verify that when session termination is triggered (such as logout or expiration), the application disallows any further use of the session. For reference tokens or stateful sessions, this means invalidating the session data at the application backend. Applications using self-contained tokens will need a solution such as maintaining a list of terminated tokens, disallowing tokens produced before a per-user date and time or rotating a per-user signing key.
- **日本語**: ログアウトや期限切れでログイン状態を終わらせたとき、それ以降そのログイン引換券が一切使えないこと。
- **判定のしかた**: 読む
- **見る場所**: 【ログイン引換券の持ちかたを調べる命令】の出力に挙がった箇所と、次の命令で挙がった文書。この2つ以外は見ない。

  ```
  grep -rlniE 'ログアウト|signOut|ログイン状態|セッション|端末|失効|期限' docs/ *.md 2>/dev/null
  ```
- **合格基準**: ログアウト後に、それまでのログイン引換券が**一切使えなくなる**ことが、コードまたは記録から分かること。次の2つを**どちらも**満たすこと。片方でも欠ければ不合格。
  1. サーバ側に持っているログイン状態が無効になること。ブラウザから消しているだけでは不合格
  2. **中身入りの引換券（発行済みで取り消せないもの）を使っている場合**、それが無効になるまでの時間が0であること。0でない場合は、無効にしたものの一覧を持つ・利用者ごとの日時より前のものを弾く、といった手当てがあること

  2を置くのは、ASVS の原文がこの場合の手当てを明示して求めているため（"Applications using self-contained tokens will need a solution such as maintaining a list of terminated tokens…"）。サーバ側のログイン状態だけを見て合格にすると、**取り消せない引換券が期限まで通り続ける穴を見逃す**。

  外部のサービスに任せている場合は、上の2点の挙動が記録に書かれていることをもって判定する。記述が無ければ**判定不能**とする。
- **該当しない条件**: 無い。
- **根拠として出すもの**: 該当箇所のファイル名と行番号。無い場合は、検索した命令とその出力。

### v5.0.0-7.4.2

- **原文**: Verify that the application terminates all active sessions when a user account is disabled or deleted (such as an employee leaving the company).
- **日本語**: 利用者のアカウントを無効にした、または削除したとき、その利用者の有効なログイン状態をすべて終わらせること。
- **判定のしかた**: 読む
- **見る場所**: 次の命令の出力に挙がった箇所。

  ```
  grep -rnoiE 'active *= *false|active *= *eq\.|\.active\b|退職|停止|無効|退会' --include='*.sql' --include='*.js' --include='*.mjs' . | grep -v node_modules | head -30
  ```

- **合格基準**: 利用者を無効化または削除したあと、**その利用者が持っている有効なログイン状態のままでは、アプリのデータに一切到達できない**こと。到達を止める判定が、その利用者が触りうる**すべての経路**に入っていること。1つでも抜けていれば不合格。

  ログイン引換券そのものを失効させているかは問わない。到達できなければ目的は達している。ただし、**ログイン引換券を失効させていない場合はその旨を判定結果に明記する**（見かけ上ログインしたままになる）。
- **該当しない条件**: 無い。
- **根拠として出すもの**: 到達を止めている判定それぞれのファイル名と行番号。経路の数と、そのすべてに入っていることを示す根拠。
