# 固定表 — V14 データ保護（Data Protection）

OWASP ASVS 5.0.0 の L1 のうち、この章に属する **2項目**。項目は公式データ
（`../asvs-5.0.0-l1.csv`）と1対1で対応し、追加・削除・統合をしない。

判定のしかたは `機械`（実行する命令が確定しているもの）か `読む`（見る場所が確定している
もの）のどちらか。どちらの命令も、**対象アプリの置き場所の最上位で `bash` で実行する**。

出典: OWASP Application Security Verification Standard 5.0.0 (CC BY-SA 4.0)。
日本語は原文からの訳で、訳の責任はこの置き場所にある（`../../adr/0004` 参照）。

## この章の共通の但し書き

- **命令には3つの種類があり、出力が0件のときの意味が逆になる。** どれに当たるかを各項目の
  「命令の種類」に書く。書いていない命令は使わない。
  - **危険な書き方を探す命令**: 0件なら**合格**。探した書き方をしていない、という意味になる
  - **備えを探す命令**: 0件なら**不合格**。在るべきものが無い、という意味になる
  - **対象の一覧を作る命令**: 0件なら**判定不能**。対象が無いのか、命令が対象アプリの書き方と
    合っていないのかを区別できないため（`../../adr/0002`・`../../adr/0006`）
- **命令の出力に紛らわしい行が出たときは、その行を読む。** 本番の画面から到達できない
  試験専用の道具だと確かめられた場合に限り、その行を数に入れない。確かめられなければ
  数に入れる。**読まずに除外しない。読んだ行はすべて、確かめた結果とともに判定結果に残す。
  出力の一部を無記録で落とさない。**
- **命令は対象アプリの置き場所の最上位で `bash` で実行し、表に書いたとおりに実行する。**
  省略や追加をしない。探す範囲に対象アプリ固有の置き場所の名前を書かない。失敗を
  `2>/dev/null` で隠さない（隠すと、別のアプリに当てたとき黙って0件＝合格になる）。

### v5.0.0-14.2.1

- **原文**: Verify that sensitive data is only sent to the server in the HTTP message body or header fields, and that the URL and query string do not contain sensitive information, such as an API key or session token.
- **日本語**: 大事な値（鍵やログイン引換券など）を、URL や問い合わせ文字列に載せないこと。載せるなら本文か見出しにすること。
- **判定のしかた**: 機械
- **命令の種類**: 危険な書き方を探す命令
- **合格基準**: 次の命令の出力が**0件**であること。1件でも出れば、その行を共通の但し書きに従って読み、本番の画面から到達する箇所であれば不合格。

  ```
  grep -rnoiE '[?&](access_token|refresh_token|token|apikey|api_key|session|password|secret)=' --include='*.js' --include='*.mjs' --include='*.html' . | grep -v node_modules
  ```

- **該当しない条件**: 無い。
- **根拠として出すもの**: 命令の出力そのものと、読んだ行についての判断。

### v5.0.0-14.3.1

- **原文**: Verify that authenticated data is cleared from client storage, such as the browser DOM, after the client or session is terminated. The 'Clear-Site-Data' HTTP response header field may be able to help with this but the client-side should also be able to clear up if the server connection is not available when the session is terminated.
- **日本語**: ログインしていたときのデータを、ログアウトや終了のあとブラウザ側から消すこと。
- **判定のしかた**: 読む
- **見る場所**: 次の命令の出力に挙がった箇所。ここに挙がらない場所は見ない。

  ```
  grep -rnoiE 'localStorage|sessionStorage|indexedDB|Clear-Site-Data|signOut|removeItem|\.clear\(' --include='*.js' --include='*.mjs' . | grep -v node_modules
  ```

- **合格基準**: 次の2つをどちらも満たすこと。片方でも欠ければ不合格。
  1. ログアウトの操作で、ブラウザに保存されたログイン引換券が消えること。対象アプリが自前で保存していない場合は、保存を任せている部品が消すことが、その部品の公式の資料または経緯の記録から分かること
  2. ログアウトのあと、ログインしていたときの画面の内容が残らないこと（画面を作り直す、入口へ戻す、等）
- **該当しない条件**: 無い。
- **根拠として出すもの**: 1と2それぞれのファイル名と行番号。任せている部品については、その資料の直リンク。
