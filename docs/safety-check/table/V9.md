# 固定表 — V9 自己完結型トークン（Self-contained Tokens）

OWASP ASVS 5.0.0 の L1 のうち、章 V9 に属する **4項目**。項目は公式データ
（`../asvs-5.0.0-l1.csv`）と1対1で対応し、追加・削除・統合をしない。

判定のしかたは `機械`（実行する命令が確定しているもの）か `読む`（見る場所が確定している
もの）のどちらか。どちらの命令も、**対象アプリの置き場所の最上位で `bash` で実行する**。

出典: OWASP Application Security Verification Standard 5.0.0 (CC BY-SA 4.0)。
日本語は原文からの訳で、訳の責任はこの置き場所にある（`../../adr/0004` 参照）。

## この章の共通の但し書き

「中身入りの引換券」とは、ログイン引換券のうち、誰であるか・いつまで有効かを自分自身に
書き込んでいるもの。受け取った側が発行元に問い合わせずに真偽を確かめられる。

- **命令には3つの種類があり、出力が0件のときの意味が逆になる。** どれに当たるかを各項目の
  「命令の種類」に書く。書いていない命令は使わない。
  - **危険な書き方を探す命令**: 0件なら**合格**。探した書き方をしていない、という意味になる
  - **備えを探す命令**: 0件なら**不合格**。在るべきものが無い、という意味になる
  - **対象の一覧を作る命令**: 0件なら**判定不能**。対象が無いのか、命令が対象アプリの書き方と
    合っていないのかを区別できないため（`../../adr/0002`・`../../adr/0006`）
- **命令の出力に紛らわしい行が出たときは、その行を読む。** 本番の画面から到達できない
  試験専用の道具だと確かめられた場合に限り、その行を数に入れない。確かめられなければ
  数に入れる。**読まずに除外しない。読んだ行はすべて、確かめた結果とともに判定結果に残す。
  出力の一部を無記録で落とさない。**
- **命令は対象アプリの置き場所の最上位で `bash` で実行し、表に書いたとおりに実行する。**
  省略や追加をしない。探す範囲に対象アプリ固有の置き場所の名前を書かない。失敗を
  `2>/dev/null` で隠さない（隠すと、別のアプリに当てたとき黙って0件＝合格になる）。



この章の4項目はすべて、**対象アプリ自身がそのログイン引換券を検証しているか**で分岐する。
検証を自前で書いていないなら、書き方を誤りようがないため該当しない。ただし
「検証していない」と「検証を任せている先が分からない」は別である。後者は判定不能とする。

【自前で検証しているかを調べる命令】

```
grep -rnoiE 'jwt|jose|jsonwebtoken|verify\(|decode\(|atob\(|HS256|RS256|alg' --include='*.js' --include='*.mjs' --include='*.sql' . | grep -v node_modules | head -30
```

### v5.0.0-9.1.1

- **原文**: Verify that self-contained tokens are validated using their digital signature or MAC to protect against tampering before accepting the token's contents.
- **日本語**: 中身入りの引換券は、中身を信じる前に、署名によって改ざんされていないことを確かめること。
- **判定のしかた**: 読む
- **見る場所**: 【自前で検証しているかを調べる命令】の出力に挙がった箇所と、次の命令で挙がった文書。この2つ以外は見ない。

  ```
  grep -rlniE 'トークン|token|検証|署名|有効期限|expiry|jwt' docs/ *.md 2>/dev/null
  ```
- **合格基準**: 次のどちらかを満たすこと。
  1. 対象アプリが自前で検証している場合、中身を使う前に署名を確かめていること
  2. 自前で検証していない場合、**検証を行っている先が記録またはコードから特定できる**こと（どの仕組みが確かめているかを名指しできること）

  どちらも示せなければ**判定不能**とする。「たぶん任せている」で合格にしない。
- **該当しない条件**: 無い。
- **根拠として出すもの**: 検証を行っている箇所、または任せ先を特定できる箇所のファイル名と行番号。

### v5.0.0-9.1.2

- **原文**: Verify that only algorithms on an allowlist can be used to create and verify self-contained tokens, for a given context. The allowlist must include the permitted algorithms, ideally only either symmetric or asymmetric algorithms, and must not include the 'None' algorithm. If both symmetric and asymmetric must be supported, additional controls will be needed to prevent key confusion.
- **日本語**: 中身入りの引換券の作成と検証に使える方式を、あらかじめ決めた一覧に限ること。その一覧に「署名なし」を含めてはならない。
- **判定のしかた**: 機械
- **命令の種類**: 危険な書き方を探す命令
- **合格基準**: 次の命令の出力が**0件**であること（「署名なし」を受け入れる指定が無い）。加えて、共通の但し書きの命令で自前の検証が0件であれば「合格（該当機能なし）」とする。

  ```
  grep -rnoiE "alg['\"]? *[:=] *['\"]?none|algorithms? *[:=] *\[[^]]*none" --include='*.js' --include='*.mjs' --include='*.json' . | grep -v node_modules
  ```

- **該当しない条件**: 対象アプリが自前でログイン引換券の作成・検証を行っていない場合。
- **根拠として出すもの**: 命令の出力そのもの。

### v5.0.0-9.1.3

- **原文**: Verify that key material that is used to validate self-contained tokens is from trusted pre-configured sources for the token issuer, preventing attackers from specifying untrusted sources and keys. For JWTs and other JWS structures, headers such as 'jku', 'x5u', and 'jwk' must be validated against an allowlist of trusted sources.
- **日本語**: ログイン引換券の検証に使う鍵は、あらかじめ設定した信頼できる出どころから取ること。ログイン引換券自身が指定してきた出どころや鍵を、そのまま信じてはならない。
- **判定のしかた**: 機械
- **命令の種類**: 危険な書き方を探す命令
- **合格基準**: 次の命令の出力が**0件**であること（ログイン引換券が指定してきた鍵の出どころをそのまま使っている箇所が無い）。加えて、共通の但し書きの命令で自前の検証が0件であれば「合格（該当機能なし）」とする。

  ```
  grep -rnoiE "['\"](jku|x5u|jwk)['\"]" --include='*.js' --include='*.mjs' --include='*.json' . | grep -v node_modules
  ```

- **該当しない条件**: 対象アプリが自前でログイン引換券の検証を行っていない場合。
- **根拠として出すもの**: 命令の出力そのもの。

### v5.0.0-9.2.1

- **原文**: Verify that, if a validity time span is present in the token data, the token and its content are accepted only if the verification time is within this validity time span. For example, for JWTs, the claims 'nbf' and 'exp' must be verified.
- **日本語**: ログイン引換券に有効期間が入っている場合、確かめた時点がその期間の中にあるときだけ受け入れること。
- **判定のしかた**: 読む
- **見る場所**: 【自前で検証しているかを調べる命令】の出力に挙がった箇所と、次の命令で挙がった文書。この2つ以外は見ない。

  ```
  grep -rlniE 'トークン|token|検証|署名|有効期限|expiry|jwt' docs/ *.md 2>/dev/null
  ```
- **合格基準**: 次のどちらかを満たすこと。
  1. 対象アプリが自前で検証している場合、有効期間を確かめていること
  2. 自前で検証していない場合、**有効期間を確かめている先が記録またはコードから特定できる**こと

  どちらも示せなければ**判定不能**とする。
- **該当しない条件**: 対象アプリが自前でログイン引換券の検証を行っておらず、かつ検証している先が特定できる場合。このときは「合格（該当機能なし）」とする。
- **根拠として出すもの**: 有効期間を確かめている箇所、または任せ先を特定できる箇所のファイル名と行番号。
