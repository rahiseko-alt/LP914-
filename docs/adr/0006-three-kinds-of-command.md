# 命令を3種類に分け、出力が0件のときの意味を種類ごとに固定する

固定表の命令には性質の違うものが混ざっている。「危険な書き方を探す命令」は0件なら合格だが、
「対象の一覧を作る命令」の0件は、対象が無いのか命令が対象アプリの書き方と合っていないのかを
区別できない。それを一律に「0件なら判定不能」と書いていたため、項目ごとに書き方が食い違い、
**同じ0件に別々の判定が付いていた**。命令を **危険な書き方を探す／備えを探す／対象の一覧を
作る** の3つに分け、0件のときの意味（合格／不合格／判定不能）を種類ごとに固定する。
各項目は「命令の種類」を必ず書き、検品プログラムがその欄の有無を見る。

## Consequences

- 「0件だったから合格」と書くには、その命令が**危険な書き方を探す命令**であると宣言して
  いなければならない。宣言のない0件は使えない。
- `機械` の項目は、**命令1つと、出力に対する条件だけ**で判定が決まる形に保つ。
  「0件でなければ中身を読んで判断する」を項目の合格基準に書かない。読む必要が生じる場合は、
  共通の但し書きの「紛らわしい行の扱い」に一本化する。そうしないと、`機械` と名乗りながら
  実際には人の判断が入り、何回やっても同じという性質が失われる。
