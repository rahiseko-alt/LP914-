# 公開されている画面への応答を見ることを、安全確認の範囲に入れる

仕様書（Issue #2）は範囲外に「対象アプリの外形的な検査。今回はコードと記録を読む範囲に
とどめる」と書いた。しかし実際には、公開されている画面へ応答を取りに行った
（3.4.1・4.4.1・12.2.1・12.2.2・13.4.1）。**これは範囲を勝手に広げた行為である。**

黙って広げたままにせず、広げたことをここに記録し、範囲の定義そのものを改める。
理由は、**その確認からしか出ない不備が実際に出た**ためである。
`12.2.1`（暗号化されていない通信で中身がそのまま返る）は、この安全確認で見つかった
もののうち最も重く、コードと記録をいくら読んでも分からない。

## 改めた範囲

**公開されている画面に対して、応答の見出しと状態番号を読み取ることまでを範囲に入れる。**
次の3つを守る。

1. **読むだけ。** 値を送り込まない、画面を操作しない、作る・直す・消すをしない。
2. **対象アプリの持ち主の許可があるものに限る。** 他人のものには当てない。
3. **実行した命令と、その出力をそのまま判定結果に残す。** 何をしたかを隠さない。

## Consequences

- 範囲を広げた分、判定できる項目が増えた（3.4.1・12.2.1・12.2.2・13.4.1・4.1.1）。
- **仕様書の「範囲外」の記述は、この ADR で置き換わる。** 仕様書側にもこの ADR への
  参照を足すこと。
- 今後、範囲を外れたことに気づいたら、**黙って続けず、その場で記録して範囲を改める**。
  気づかずに続けるのと、記録して改めるのは別である。
