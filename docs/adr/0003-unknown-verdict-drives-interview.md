# 判定不能は掘り下げヒアリングで解消し、答えを対象アプリの記録に書き戻す

判定不能を「これで良いですか」と1問尋ねても、非エンジニアは技術を判断できないため追認するしかなく、
判定にならない。そこで判定不能が出たら `grilling`（掘り下げヒアリング）を起動し、技術ではなく
業務の事実を、推奨する答えを添えて尋ねる。得た答えは対象アプリ側の経緯の記録に書き戻す。

## Consequences

次回の安全確認では、その項目は経緯の記録から判定できるようになる。よって判定不能は回すたびに減り、
増えない。これが安全確認が終わりに向かう仕組みである。書き戻し先を共有側ではなく対象アプリ側に
置くのは、記録がコードから離れると必ず古くなるため。
